Tasks API reference

Create and retrieve tasks in an Atlas workspace.

Audience: DevelopersContent type: Endpoint referenceProduct: Fictional sample
Sample note: This API and its responses are fictional examples for portfolio demonstration. They are not a live service contract.

Base URL

https://api.atlas.example.com/v1

Authentication

Send an API token in the Authorization header. Treat tokens as secrets and do not include them in client-side code or public repositories.

Authorization: Bearer YOUR_API_TOKEN

Create a task

POST /workspaces/{workspace_id}/tasks

Creates a task in the specified workspace.

Path parameters

ParameterTypeDescription
workspace_idstringUnique identifier of the workspace.

Request body

FieldTypeRequiredDescription
titlestringYesTask title. Must contain 1–120 characters.
descriptionstringNoAdditional task details.
due_datestringNoDue date in ISO 8601 format (YYYY-MM-DD).

Example request

curl -X POST \
  "https://api.atlas.example.com/v1/workspaces/ws_123/tasks" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Review onboarding guide",
    "description": "Check links and screenshots",
    "due_date": "2026-12-01"
  }'

Example response

{
  "id": "task_789",
  "title": "Review onboarding guide",
  "description": "Check links and screenshots",
  "due_date": "2026-12-01",
  "status": "open",
  "created_at": "2026-11-12T14:30:00Z"
}

Response codes

CodeMeaningRecommended action
201Task created.Store the returned task ID.
400Invalid request.Check required fields and field formats.
401Authentication failed.Verify the API token.
404Workspace not found.Check the workspace ID and access.
429Rate limit exceeded.Wait before retrying; use backoff.

Writing decisions demonstrated

  • Endpoint purpose and HTTP method are easy to scan.
  • Parameters and request fields are defined in tables.
  • Examples show a complete request and response.
  • Error codes include actionable next steps.
